# 测试平台赋能宣传文档

## 平台定位

测试平台是一套面向测试人员的 AI 辅助测试工作台，围绕测试人员的日常工作流程，把需求理解、测试设计、自动化脚本、测试执行、失败修复、回归验证和质量证据沉淀串联起来。

它的核心价值不是“替测试人员做判断”，而是把重复、耗时、容易遗漏的工作自动化，让测试人员更快完成测试准备、更高效执行回归、更清楚地定位问题，并持续沉淀可复用的测试资产。

## 它能帮测试人员解决什么问题

| 测试人员日常痛点 | 平台赋能方式 | 带来的好处 |
| --- | --- | --- |
| 需求文档长，人工拆模块耗时 | 自动从需求中识别业务模块、测试点和风险点 | 更快完成测试分析，减少遗漏 |
| 写测试计划重复、费时间 | 根据模块和页面信息生成可审查的测试计划 | 测试人员从“从零编写”变成“审查优化” |
| 自动化脚本编写门槛高 | 根据测试计划生成 Playwright 自动化脚本 | 降低自动化落地门槛 |
| 执行结果分散，不方便复盘 | 统一展示执行状态、日志、报告、视频 | 问题定位更直接，沟通证据更充分 |
| 脚本失败后排查成本高 | AI 根据失败现象辅助修复脚本 | 缩短脚本维护时间 |
| 回归测试需要反复手工组织脚本 | 支持测试集管理和一键执行 | 回归执行更标准、更省时 |
| 写库用例污染测试环境 | 执行前自动恢复数据库基线 | 写库流程可以重复验证 |
| 计划和脚本版本混乱 | 自动记录版本、来源和执行记录 | 测试资产可追溯、可回滚、可交接 |

## 核心功能

### 1. 需求解析：从需求文档快速提炼测试方向

测试人员可以把需求文档上传到平台，平台会辅助完成第一轮测试分析：

- 识别需求中涉及的业务模块
- 提炼每个模块的测试点
- 标记可能涉及写库、审批、状态流转的风险场景
- 匹配系统页面、菜单、账号、关键控件等测试上下文
- 生成后续测试计划所需的提示词

测试人员不需要从空白文档开始拆需求，可以直接在平台生成的候选模块基础上做确认、调整和补充。

**效率提升：** 缩短需求分析启动时间，帮助测试人员更快进入测试设计阶段。

### 2. 测试计划生成：把测试思路沉淀成可检查的计划

平台可以根据确认后的模块和测试点生成测试计划。测试计划不是黑盒结果，测试人员可以直接查看、编辑、保存和删除。

它可以帮助测试人员快速形成：

- 主流程测试场景
- 操作步骤
- 预期结果
- 前置条件
- 导航路径
- 关键校验点
- 风险说明

平台更适合先覆盖稳定、可维护的正向主流程，帮助团队快速建立自动化基础用例。

**效率提升：** 测试人员从“手工写计划”变成“审查和优化计划”，减少重复文字工作。

### 3. 脚本生成：从测试计划快速落地自动化

测试计划确认后，平台可以继续生成 Playwright 自动化脚本。

测试人员可以在平台内：

- 从某条测试计划生成脚本
- 查看脚本内容
- 编辑脚本
- 执行脚本
- 删除不需要的脚本
- 查看脚本来源计划

这让自动化不再完全依赖手工编码。对于测试人员来说，更重要的是可以把测试设计快速转化为可执行脚本。

**效率提升：** 降低自动化脚本编写门槛，加快从手工测试到自动化测试的转化。

### 4. 脚本执行：一键运行并保留完整证据

平台支持单条脚本执行、模块批量执行和测试集执行。执行过程中会实时展示日志，执行完成后统一保存结果和证据。

测试人员可以看到：

- 脚本是否通过
- 执行耗时
- 执行日志
- Playwright 报告
- 执行视频
- 失败信息
- 历史执行记录

执行视频尤其适合问题复盘。测试人员可以直接看到浏览器当时做了什么、停在了哪里、页面出现了什么现象。

**效率提升：** 减少“复现不清楚、证据不完整、沟通靠描述”的问题。

### 5. 失败修复：降低自动化维护成本

自动化脚本失败后，测试人员可以在平台中发起修复。平台会根据失败日志、页面状态和执行结果辅助分析问题，并尝试修复脚本。

适合处理的问题包括：

- 页面元素变化
- 定位器失效
- 断言不稳定
- 页面加载时机变化
- 测试数据状态变化
- 脚本步骤需要微调

修复后，测试人员仍然可以查看修改内容、再次执行验证，并决定是否继续调整。

**效率提升：** 失败脚本不再完全依赖人工逐行排查，维护成本明显降低。

### 6. 测试集管理：让回归测试标准化

平台支持把多条脚本组织成测试集。测试人员可以按业务流程、模块、版本或回归范围维护测试集。

测试集支持：

- 新增测试集
- 添加脚本
- 移除脚本
- 调整执行顺序
- 重命名
- 删除
- 一键执行
- 查看历史执行记录

测试集适合用于冒烟测试、版本回归、上线前验证和核心业务链路巡检。

**效率提升：** 回归测试从“临时挑脚本执行”变成“固定测试集一键执行”。

### 7. 数据库基线：让写库测试可以反复跑

很多业务系统的测试会涉及新增、修改、审核、驳回、删除、改密码等写库动作。没有环境恢复能力时，用例跑几次后数据就会变脏，影响后续测试。

平台支持在执行前恢复数据库基线，让写库流程可以重复验证。

适合场景：

- 清收录入
- 清收审核
- 用户管理
- 角色管理
- 修改密码
- 其他会改变业务状态的数据流转场景

**效率提升：** 降低测试数据维护成本，让自动化脚本更稳定、更可重复。

### 8. 资产版本管理：测试成果可追溯、可交接

平台会把测试计划和自动化脚本作为测试资产管理。

测试人员可以追溯：

- 计划是谁生成或修改的
- 脚本来源于哪条计划
- 当前脚本是第几版
- 某次执行跑的是哪一版脚本
- 历史版本能否恢复
- 某次失败对应的日志、报告和视频

这让测试资产不再散落在个人电脑、聊天记录或临时文件里，而是沉淀成团队可持续维护的质量资产。

**效率提升：** 降低交接成本，方便复盘问题，也方便持续迭代自动化测试。

### 9. 多项目工作区：不同系统独立管理

平台支持多个项目。不同项目的需求、计划、脚本、测试集、执行记录和产物互相隔离。

适合测试团队同时维护多个系统、多个版本或多个测试环境。

**效率提升：** 避免不同项目测试资产混乱，方便团队统一管理。

### 10. Agent 自动测试：从需求到回归的一站式流水线

除了逐步操作，平台还提供 Agent 自动测试模式。测试人员上传需求后，Agent 可以按阶段推进完整流程：

1. 需求解析
2. 模块审查
3. 测试计划生成
4. 测试计划审查
5. 脚本生成
6. 脚本执行
7. 失败脚本修复
8. 测试集创建
9. 测试集执行

每个阶段都有状态和产物，测试人员可以查看过程、取消任务，也可以在失败后恢复执行。

**效率提升：** 适合演示端到端能力，也适合快速从需求拉起一批可执行的自动化资产。

## 对测试工作的整体提升

### 1. 测试准备更快

需求解析、模块拆分、测试点提炼和测试计划生成都可以由平台先产出草稿，测试人员再审查补充。准备阶段的主要工作从“从零开始写”变成“基于初稿把关”。

### 2. 自动化落地更快

测试人员不需要完全依赖手工编码，可以从测试计划直接生成脚本，并在平台内执行和维护。自动化门槛降低后，更多手工测试场景可以逐步沉淀为自动化资产。

### 3. 执行反馈更完整

平台把执行结果、日志、报告和视频放到一起。失败时，测试人员可以快速判断是脚本问题、数据问题、环境问题还是业务系统问题。

### 4. 回归测试更稳定

测试集让回归范围固定下来，数据库基线让写库流程可重复执行，历史执行记录让每轮回归都有迹可查。

### 5. 团队协作更顺畅

测试计划、脚本、版本、执行记录和视频都集中管理。测试、开发、业务沟通问题时，可以直接基于同一份证据讨论，减少反复复现和口头解释。

## 推荐宣传话术

### 简短版

这套测试平台把测试人员从需求分析到自动化回归的关键工作串起来。AI 负责提速，测试人员负责把关；平台负责沉淀计划、脚本、执行记录、报告和视频，让测试工作更高效、更可追溯、更容易复用。

### 面向测试人员

以前我们做自动化，难点不只是写脚本，而是需求怎么拆、计划怎么写、脚本怎么维护、失败怎么复现、回归怎么组织。这个平台把这些工作放到同一个工作台里，帮助测试人员更快完成测试设计，更快生成自动化脚本，更方便执行和修复，最后沉淀成可以持续复用的测试资产。

### 面向测试负责人

平台提升的不只是单次执行效率，而是整个测试资产的管理效率。需求、计划、脚本、执行结果、失败证据和版本记录都可以持续沉淀，团队交接、回归执行、问题复盘和自动化维护都会更清晰。

## 推荐演示重点

1. 上传需求，展示平台如何识别模块、测试点和风险。
2. 打开候选模块，展示测试人员可以审查和调整。
3. 生成测试计划，展示计划可读、可编辑。
4. 从计划生成脚本，展示自动化快速落地。
5. 执行脚本，展示日志、报告和视频。
6. 发起失败修复，展示脚本维护提效。
7. 创建测试集并执行，展示回归测试标准化。
8. 展示资产版本和历史执行记录，强调可追溯和可交接。
9. 展示 Agent 自动测试模式，强调从需求到回归的完整流水线。
